PURPOSE
Add the real isolation prerequisite for eventually reproducing a proposed bounded Python
recipe's caller-supplied adversarial-test claims. The upgrade must fail closed when the host
cannot enforce the boundary and must not substitute JavaScript parsing, node:vm, or Node's
permission model for malicious-code isolation.

PRIMARY BOUNDARY REFERENCES
- Node permission model: https://nodejs.org/api/permissions.html
  The official documentation describes it as a seat belt for trusted code, not a security
  guarantee against malicious code.
- Node vm: https://nodejs.org/api/vm.html
  The official documentation explicitly says node:vm is not a security mechanism.
- Bubblewrap: https://github.com/containers/bubblewrap
  Bubblewrap supplies the empty mount namespace and separate user/PID/IPC/UTS/network
  namespaces; the calling arguments remain the policy.

IMPLEMENTED BOUNDARY
bounded-python-recipe-replay-isolation-hand.js:
- binds one proposal digest, caller-evidence digest, live six-file observation, evidence-root
  identity, and live toolchain observation;
- emits an expiring, digest-bound receipt for one fixed policy;
- accepts no caller command, module path, source bytes, runner, mount, or environment;
- never reads proposal source bytes itself and never mounts proposal/workspace bytes;
- never imports or executes proposed modules or caller tests;
- if all providers are usable, executes only a fixed trusted probe through prlimit + bwrap;
- if any required provider is unavailable, emits a qualified hold and starts no policy probe.

POLISH CORRECTION
The first draft used the existing Python-oriented 256 MiB address-space ceiling. A direct
trusted compatibility probe showed modern Node could not initialize under that virtual-memory
limit. The final policy uses a still-bounded 2 GiB ceiling; the exact trusted Node startup
probe passed under the final CPU/address-space/file/process/core envelope. Proposal code was
not involved in either compatibility probe.

TRUTH BOUNDARY
This checkpoint certifies no sandbox on the current host and executes no caller code. It proves
that the system detects the missing namespace capability, binds that result to the proposal and
observations, refuses stale/tampered/mismatched receipts, and prevents the admission descriptor
from silently erasing the replay gap. A receipt digest is not proof of author identity, consent,
or Hand origin. Even a passing fixed policy probe would not reproduce caller tests, prove source
semantics, establish human review, authorize replay, activate a recipe, or grant promotion.
